## Known provenance gaps

1. **Placeholder coverage is complete but not final art.** Every C-7 key resolves; none
   is a locked third-party image.
2. **Item sprite-key naming is inconsistent.** Existing content uses camelCase item ids
   in `spriteKey` (for example `trinket.quantumSplitterCoil`), while
   `tools/assets`' default item catalog uses kebab-case ids (for example
   `trinket.quantum-splitter-coil`). Today this only affects placeholder naming, but it
   must be normalized before locking real item art.
3. **No imagegen output exists.** The brief and key list are preparation, not delivery.
4. **No asset verification was run in this docs task.** Run `pnpm assets:build` and
   `pnpm assets:verify` before making any claim about locked assets, byte identity, or
   atlas size.
5. **The trailer's art path is placeholder/vector based.** Do not describe it as final
   sprite art.

## Asset checklist for a real art drop

1. Put approved files under the contracted delivery root and record their source and
   licence.
2. Build an assetrizz-format manifest with SHA-256 for every locked file.
3. Align content item ids and the `tools/assets` catalog naming.
4. Run `pnpm assets:build` and `pnpm assets:verify`.
5. Review the contact sheet for style consistency and invented boss faces.
6. Record real/placeholder counts and atlas size.
7. Re-render the trailer with the supplied resolver only if the asset rights allow it.
8. Update this page with the actual evidence, date, and any remaining placeholders.
