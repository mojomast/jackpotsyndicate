This page records what is actually committed, what is generated, and what is still
missing. It does not claim final art or rights that have not been verified.

## Software and licences

- The repository has no top-level `LICENSE` file; the spec records "all rights reserved
  for now" (D-13). This is not a permissive open-source release.
- Runtime libraries include GSAP, React, PixiJS, Zustand, Zod, and Vite/Rolldown tooling.
  Their upstream licences apply. This repository does not currently ship a consolidated
  third-party licence bundle; review upstream terms before public distribution.
- `packages/anim` depends on GSAP 3.15.1 and HyperFrames 0.9.47 (the latter for
  composition lint/render tooling). The animation package's own README and REVIEW files
  record its verification context.

## Known provenance gaps

1. **Working batch, not final art.** 67 of 71 keys are locked; four placeholder keys remain. The handoff records quality issues: diamond token is cyan rather than blood-red, skull token lacks the magnet, boss portraits are tightly framed, `chassis.harness-hyper` reads as wearable gear, and UI nine-slicing has not been tested in the game.
2. **Item sprite-key naming is now normalized.** Content uses canonical kebab-case keys (`trinket.quantum-splitter-coil`, `glyph.blood-diamond`, `chassis.harness-hyper`, etc.) and the content test rejects non-canonical item keys.
3. **No packed atlases.** The current pipeline copies per-key PNGs and records atlas labels/frames; it does not pack pixel atlases. The committed output is 1,484,177 bytes (1.42 MiB) as a directory, not a verified 1.5 MB atlas.
4. **Asset verification was run on the working branch.** `tools/assets build` reported 71 keys / 67 locked / 4 placeholders and `verify` checked 73 files. This does not establish final art rights, browser rendering everywhere, or trailer re-render.
5. **The trailer's art path is still placeholder/vector based.** Do not describe it as final sprite art.

## Asset checklist for a real art drop

1. Put approved files under the contracted delivery root and record their source and
   licence.
2. Build an assetrizz-format manifest with SHA-256 for every locked file.
3. Align content item ids and the `tools/assets` catalog naming.
4. Run `pnpm assets:build` and `pnpm assets:verify`.
5. Review the contact sheet for style consistency and invented boss faces.
6. Record real/placeholder counts and atlas size.
7. Re-render the trailer with the supplied resolver only if the asset rights allow it.
8. Update this page with the actual evidence, date, and any remaining placeholders.
